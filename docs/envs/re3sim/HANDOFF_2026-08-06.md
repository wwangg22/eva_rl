## 5. ⭐ Every bug found, and the lesson

Eight of these were mine. The pattern is consistent enough to state up front: **a check that
looks rigorous and prints a confident number is not thereby testing what it claims.** Each
passed review by inspection and failed only when someone looked at the numbers it produced.

### 5.1 "Up" from the point distribution instead of the cameras — *nearly cost a re-shoot*

`extract_object.py` picked the support plane's sign by comparing extreme height percentiles.
Sound when the object and noise are the only things off-plane; **wrong when the capture
contains a room** — the far field owns the bigger tail, the normal flips to point *into* the
table, and everything above the desk reads as below it. **All four objects looked ABSENT** and
I told the user to re-shoot. Fixed with `--up-hint` derived from the COLMAP camera centres.

> **Lesson:** when a pipeline reports the *input* is bad, suspect the pipeline first — that
> conclusion conveniently ends the investigation and it is the one that costs the user a
> re-shoot.

### 5.2 The scale gate compared a dimension against itself

Held back "longest axis" — which for a cube **is** its height, the axis used to set the scale.
Passed a **28.0 × 22.9 × 56.3 mm** mesh as a 56 mm cube.

> **Lesson:** a held-back check is only a check if it is independent of the thing being fitted.

### 5.3 The gate reported *after* it wrote

`GATE FAIL` printed immediately after `-> .../cube.usda`. Both true; together, a corrupted env,
because `_reconstructed_or` picks an asset up the moment the file exists.

> **Lesson:** a check placed after the side effect it guards is not a check.

### 5.4 The gate compared the wrong axis pair when one is unknown

Dropped the `None`s and truncated, shifting every axis past the gap: the tape measure's 68.77 mm
*middle* axis was scored against the 36 mm *height* → "+91 % FAIL" on a mesh that is really
+6.6 %. Fixed by comparing **by rank**.

### 5.5 The splats had no yaw — *found only by rendering*

The marker→env transform applied height, not rotation. Measured workspace coverage of the
reconstructed desk: **14 %**. Every object spawned over bare ground. **Nothing automated could
see it** — splats are visual-only, so every predicate, smoke test and success rate was
bit-identical either way. Now 91.3 % at yaw 180°.

> **Lesson:** anything the MDP does not read is invisible to every automated check you have.
> Render it and look.

### 5.6 `reversed()` on both halves of the transit chain — *cost a day*

```python
up_pts = list(reversed(_densify(grip, pre))) + list(reversed(_densify(pre, high)))
```
`_densify(a,b)` already runs a→b. Reversing both put `high` in the **middle**, leaving the
transit endpoint near the pre-grasp. Nine variants and a day of drive/gravity hypotheses.

Caught by reporting the achieved TCP against **two** references at the same instant:

| vs | error |
|---|---|
| `high` (Cartesian target) | **101.6 mm** |
| `high_fk` (FK of the commanded pose) | **7.5 mm** |

The arm went exactly where it was sent. **101.6 → 1.0 mm.**

> **Lesson:** "the robot did not reach the target" and "the plan did not target that" produce
> the same position error. Always measure against the commanded pose as well.

### 5.7 The episode horizon did not move when the manoeuvre did

Demos including the transit run **1018–1118** env steps; `episode_length_s = 16.0` gave **800**.
Every evaluation episode truncated mid-transit: 3.4 % with `no_lift` 91.9 %. Raised to 26 s
→ **7.8 %**.

> **Lesson:** the horizon is a property of the manoeuvre, not a config constant.

### 5.8 Two grip heights, both honest measurements of the wrong thing

* **25 mm** — `p01` on an **analytic** cube.
* **32 mm** — a sweep using `--teleport-pregrasp`, which under §5.6's bug started the arm
  effectively **at** the cube: a grasp with no descent, hence no sag.
* **56 mm** — end-to-end, and *above* the cube's own 54.5 mm top, because the **settled** tool
  centre is what lands on it. On a position-driven arm, commanding the height you want is
  commanding the wrong thing.

> **Lesson:** a protocol that skips part of the manoeuvre cannot measure a constant of the
> manoeuvre, however careful and reproducible it is.

### 5.9 `settle_bias` cancelled itself

Teleported to `qb + bias` then drove at `qb + bias` → no error → `bias += −bias` → converges to
zero. Fixed (teleport to `qb`, drive at `qb + bias`), but it **still hurts** (52 → 71 mm) and is
**off** behind `SETTLE_BIAS=1`.

### 5.10 The runtime bias integrator was actively harmful

12.5 % with it, **32.8 %** without. Tuned to converge inside a 30-step descent it necessarily
overshoots on arrival; at a ±0.80 rad clamp it drove the cube from z = 28 mm to 11.5 mm.

### 5.11 Smaller ones, recorded so they are not re-hit

- `--verbose` collides with `AppLauncher`'s → use `--chatty`.
- argparse reads a leading `-` as an option name: pass vectors as `--up-hint=-0.1,...`.
- `pkill -f finish_object_asset` also kills the job you just started.
- Editing a running bash script corrupts it — bash reads by byte offset.
- A standalone `Camera` is never initialised; put it in the **scene config**.
- `Usd.Stage.CreateNew` refuses to overwrite — `os.remove` first.
- ROI voxel must be sized to the **object** (~height/100), not to the cloud's spacing: 21 M
  points → 651 k, minutes → seconds per attempt.
- `| grep | tail` in a background job buffers until EOF: **redirect to a log file**.
- Isaac Sim's first import takes minutes. Slow startup is not a hang.

### 5.12 Inherited: six `reconstruct.py` breaks

pycolmap `FeatureExtractionOptions`; `SequentialPairingOptions`; faiss-vs-flann vocab tree
(→ exhaustive matching); CUDA-less pycolmap wheel (→ CPU matching); `colmap`/OpenMVS binaries
living in a **different conda env** from `pycolmap` (append `tools/bin` to `PATH`, never
prepend — it shadows `python`); `ReconstructMesh -p` does not exist in v2.1.0 **and was
unchecked**, so a missing mesh flowed onward and the stage was marked complete.

## 6. What worked

- **The failure taxonomy, every single time.** `lifted-but-lost = 0` and
  `over-box-not-inside = 0` from the very first expert run said the manoeuvre was fine and the
  loss was upstream — true for a day and a half, and it kept me off the carry height and the
  finger stiffness, neither of which was ever broken.
- **Built-in positive controls.** `control_24` failing is what exposed two bad searches.
- **Negative controls written first.** All 8 `placed_mask` controls, including a rotated-box
  case an axis-aligned test would get wrong.
- **Rendering the scene.** The only thing that could ever have found §5.5.
- **Independent second methods.** Colour found the cube when geometry could not; the cameras
  settled the up-direction when the point distribution could not; `high_fk` separated planner
  from execution when a single position error could not.
- **Measurement-driven correction instead of grid search.** `footprint_expand` is *solvable*
  from the observed footprint ratio; iterating it converges in two steps where a blind sweep
  never found it.
- **`_kin.ArmKin`** — batched FK read back from the sim, hinged-cost CEM with restarts and
  keep-out boxes, DLS `refine`, MDP-bypassing `hold_phys`. The single most reusable asset here.

## 8. Plan from here — *subject to change*

### Immediate

1. **Get the two user answers** (§7) and update `mdp/common.py`'s `BOX_OUTER_X/Y` and the splat
   yaw. Re-run `author_workstation_box_usd.py`, then `test_workstation_env.py`.
2. **Finish the scaling curve.** `run_final3.sh` (4096 eps / 140 k) is running. If it is still
   climbing, run 8192. Collection costs ~80 min per 2048 episodes.

### Then, in order of expected value

3. **Raise the expert above 30 % — this is now THE lever.** BC retains ~64 % of it across two
   independent runs and the data curve is flat, so the policy is close to its ceiling. Every
   expert point is worth ~0.64 policy points.
   - `no_lift` dominates → the grasp. Sweep `STANDOFF` (75 mm) and `O_ALIGN_MIN` (0.90) exactly
     the way `GRIP_Z` was swept — **end-to-end**, never under teleport.
   - The ~35 mm descent sag is currently absorbed by a single constant. A *per-pose* correction
     that actually works would decouple it; see §5.9/§5.10 for the two that did not.
4. **DAgger.** Now better targeted than before: the failures are concentrated in two named
   modes (`no_lift` 72.9 %, `near_miss` 6.8 %), the expert is available to relabel, and both
   are states the policy actually visits. This is the standard answer to a flat BC curve.
5. **Sweep `CARRY_Z` (0.175) end-to-end.** `near_miss` went 0.8 % → 6.8 % as the policy learned
   to lift more, i.e. some of the loss has migrated from the grasp to the release. That is a
   cheaper problem than the grasp and the sweep is the same shape as `GRIP_Z`'s.
6. **`-Strict-v0`.** Clutter displacement is already 0.03–0.04 mm, so this may nearly pass.
7. **Vision distillation.** `record_video.py` already mounts the user's validated
   `WRIST_CAM_CFG` (D405, 84° HFOV, `tilt_x_m30`, optical axis 1.8° off the TCP). The splats
   render natively, so photoreal pixels are available today for a teacher→student pass.
8. **Real-hardware bring-up.** Marker → arm-base calibration; the yaw and box dimensions above
   stop being cosmetic and become load-bearing.

### Do not repeat

- Do **not** trust a sweep run under `--teleport-pregrasp` for any constant of the full
  manoeuvre (§5.8).
- Do **not** re-derive the transit's root cause — it is fixed (§5.6), and the diagnostic that
  found it (`high` vs `high_fk`) is still wired into `collect_demos.py`.
- Do **not** re-shoot the object captures. They are fine (§5.1).
- Do **not** re-enable either bias mechanism without re-measuring; both made things worse.

## 9. Machine notes

- `source ~/miniconda3/etc/profile.d/conda.sh && conda activate env_isaaclab6`
- **Never invoke Isaac Sim through the env's python binary directly** — segfaults on a
  `CXXABI_1.3.15` mismatch ~1 s into Kit startup. Always go through activation.
- Reconstruction needs **both** envs: `pycolmap`/`open3d`/`plyfile`/`pxr` in `env_isaaclab6`,
  the `colmap` CLI and OpenMVS binaries in `tools`. **Append** `~/miniconda3/envs/tools/bin` to
  `PATH`; prepending shadows `python`. PATH only — never `LD_LIBRARY_PATH`.
- 10 GB RTX 3080, shared. 3DGS peaks ~9.5 GB — run nothing else beside it. A 128-env expert
  batch is ~2 GB; BC training ~3 GB; evaluation ~2 GB.
- **Long jobs: Bash `run_in_background: true`, not `systemd-run`** (user instruction, and
  harness jobs wake the agent on completion). Always redirect to a log file.
- `python -u` always.
- OpenMVS v2.1.0 binaries exit 1 on `--help` by design.
